    1 Visão geral
    
        
    Treinamos do zero uma Rede Neural Convolucional (CNN) que recebe a foto de um
          rosto e diz qual integrante do grupo ela é.
    
        
    Não usamos modelo pré-treinado nem detector de rosto pronto: todo o tratamento das imagens e as métricas foram
          programados por nós com NumPy. A biblioteca TensorFlow/Keras é usada só para montar e treinar a rede.
    
        
    

        
    O caminho de uma foto
    
        
      
          
    1. Foto da webcamdataset/<nome>/
      2. 
          
    2. Pré-processamento96×96, cinza, 0–1
      3. 
          
    3. Divisãotreino · validação · teste
      4. 
          
    4. Aumentosó no treino
      5. 
          
    5. CNN4 convoluções
      6. 
          
    6. TreinoAdam + EarlyStopping

    2 Coleta das fotos
    
        
    A rede aprende com exemplos: precisamos de muitas fotos do rosto de cada integrante, cada um na
          sua pasta.
    
        
    dataset/
├── ana/     ana_0000.jpg, ana_0001.jpg, ...
├── bruno/   ...
└── carla/   ...
    
        
    O nome da pasta é o rótulo que a rede vai aprender. As fotos podem ser tiradas na própria
          página (área “Preparar o modelo”, passo 1) ou copiadas para a pasta.
    

        
    Passo a passo da coleta pelo site
    
        
      
          
    1. Escolher o nome. O nome digitado vira o nome da pasta, então ele é padronizado: minúsculas,
            sem acento e sem espaço (“Ana Clara” vira ana_clara).
      2. 
          
    2. Ligar a câmera e esperar 3 segundos. O navegador pede permissão para usar a webcam e faz uma
            contagem regressiva para a pessoa se posicionar.
      3. 
          
    3. Tirar as fotos. A cada 250 ms, o quadro do vídeo é copiado para um <canvas>
            e transformado em JPEG, guardado como texto (base64). Com 80 fotos, são 20 segundos.
      4. 
          
    4. Enviar e salvar. As fotos vão para o servidor, que as grava em dataset/<nome>/
            continuando a numeração (se já havia 80 fotos, a próxima é a _0080). Se a opção estiver marcada, o
            treino começa em seguida.
            
      
              Ver no código

        2. 
                
      2. Passo 2: pede ao navegador acesso à webcam.
        3. 
                
      3. Passo 2: contagem regressiva de 3 segundos, um número por segundo.
        4. 
                
      4. Passo 3: copia o quadro atual do vídeo como JPEG (qualidade 90%) e guarda na lista.
        5. 
                
      5. Passo 3: espera 250 ms antes da próxima foto.
        6. 
                
      6. Passo 4: envia o nome e todas as fotos ao servidor.
        7. 
                
      7. Passo 4: se “Treinar automaticamente” estiver marcado, já começa o treino.
        8. 
              
      
            
      
            
      
              Ver no código
              
      
              
        
                
      1. Cria a pasta do integrante, se ela ainda não existir.
        2. 
                
      2. Conta quantas fotos a pasta já tem, para continuar a numeração.
        3. 
                
      3. Tira o cabeçalho data:image/jpeg;base64, e converte o texto de volta nos bytes do JPEG.
        4. 
                
      4. Monta o número com 4 dígitos: 7 vira “0007”.
        5. 
                
      5. Grava o arquivo nome_0007.jpg no disco.
        6.

      •

      •

    3 Leitura
    
        
    Antes de tudo, transformamos as pastas em duas listas: onde está cada foto e de quem ela é.
    
        
      
          
    1. Cada pasta é um integrante. As pastas são ordenadas pelo nome e numeradas: a primeira é a
            pessoa 0, a segunda é a pessoa 1, e assim por diante. Pastas que começam com . ou _
            (do sistema) são ignoradas.
      2. 
          
    2. As fotos são lidas na ordem em que foram tiradas. Como os arquivos são numerados
            (ana_0000, ana_0001...), a ordem alfabética é a ordem de captura. Isso vai importar
            na divisão dos dados (seção 5).
            
      
              Ver no código
              
      
              
        
                
      1. Lista as subpastas em ordem alfabética: essa é a lista de integrantes.
        2. 
                
      2. Ignora pastas que começam com “.” ou “_”.
        3. 
                
      3. Dá um número a cada integrante (0, 1, 2...), que é o rótulo usado pela rede.
        4. 
                
      4. Percorre as fotos em ordem alfabética, que é a ordem de captura.
        5. 
                
      5. Guarda o caminho da foto e, na mesma posição, o número da pessoa.
        6. 
              
      
            
      
          
      3. 
          
    3. Cada arquivo vira uma matriz de números. Uma foto colorida vira uma matriz
            altura × largura × 3: para cada pixel, os valores de vermelho, verde e azul (0 a 255).
      4. 
          
    4. Fotos “deitadas” são desviradas. Celulares às vezes salvam a foto deitada e anotam a rotação
            certa nos metadados (EXIF). Nesse caso, giramos a matriz.
            
      
              Ver no código
              
      
              
        
                
      1. Abre o arquivo. É o único uso do PIL: ler (e salvar) imagens.
        2. 
                
      2. Lê a orientação anotada pela câmera (código 274 do EXIF; 1 = normal).
        3. 
                
      3. Transforma a imagem em uma matriz NumPy (altura, largura, 3).
        4. 
                
      4. Foto de cabeça para baixo: gira 180°.
        5. 
                
      5. Foto deitada: gira 90° no sentido horário (o 8 é o anti-horário).
        6. 
              
      
            
      
          
      5. 
        
    
      
    

      
      
    
        
    4 Pré-processamento
    
        
    Toda foto, de qualquer tamanho, vira uma imagem de 96×96 em tons de cinza, com valores entre 0 e 1:
          o formato que a rede espera.
    
        
    A mesma função é usada no treino e no reconhecimento ao vivo: se fossem diferentes, a rede veria
          ao vivo imagens diferentes das que aprendeu. São 5 etapas, cada uma uma função curta feita com NumPy:
    
        
        
      
          
    1. Recorte central. Cortamos o maior quadrado do centro da foto. Uma foto de 640×480 vira
            480×480 (sobram 80 pixels de cada lado). Por quê: a rede exige entrada quadrada, e cortar não deforma o
            rosto; redimensionar direto o achataria.
            
      
              Ver no código
              
      
              
        
                
      1. O lado do quadrado é a menor dimensão (480 em uma foto 640×480).
        2. 
                
      2. Quanto sobra em cima: metade da diferença (0 nesse exemplo).
        3. 
                
      3. Quanto sobra à esquerda: (640 − 480) / 2 = 80.
        4. 
                
      4. Recorta a matriz: linhas de topo até topo+lado, colunas de esquerda até esquerda+lado.
        5. 
              
      
            
      
          
      2. 
          
    2. Tons de cinza. Cada pixel vira um único número, uma média ponderada das cores:
            0,299·R + 0,587·G + 0,114·B (o olho humano é mais sensível ao verde). Por quê: a identidade
            está na forma do rosto, não na cor; com 1 canal em vez de 3, a rede fica menor e depende menos da iluminação.
            
      
              Ver no código
              
      
              
        
                
      1. Multiplica o canal R (índice 0), G (1) e B (2) pelos pesos e soma, para todos os pixels de uma vez.
        2. 
              
      
            
      
          
      3. 
          
    3. Redimensionamento para 96×96. Primeiro fazemos a média de blocos: em uma imagem de
            480×480, cada bloco de 5×5 pixels vira 1 pixel com a média deles. Depois, o vizinho mais próximo garante
            o tamanho exato quando a conta não é inteira. Por quê: menos pixels deixam o treino rápido, e a média
            evita o serrilhado de pegar só 1 pixel a cada 5.
            
      
              Ver no código
              
      
              
        
                
      1. Quantos pixels originais cabem em 1 pixel novo: 480 // 96 = 5.
        2. 
                
      2. Descarta as sobras da borda para a divisão em blocos ficar exata.
        3. 
                
      3. Separa a imagem em blocos 5×5 (eixos 1 e 3) e tira a média de cada bloco.
        4. 
                
      4. Para cada pixel novo, calcula qual pixel da imagem anterior corresponde a ele.
        5. 
                
      5. Pega esses pixels (linhas e colunas): o resultado tem exatamente 96×96.
        6. 
              
      
            
      
          
      4. 
          
    4. Equalização de histograma. Contamos quantos pixels há de cada tom (o histograma), acumulamos
            essa contagem e usamos o acumulado para espalhar os tons por toda a faixa de 0 a 255. Por quê: uma foto
            escura e uma clara da mesma pessoa ficam parecidas.
            
      
              Ver no código
              
      
              
        
                
      1. Converte para números inteiros de 0 a 255 (cada tom é um inteiro).
        2. 
                
      2. O histograma: quantos pixels existem de cada tom, de 0 a 255.
        3. 
                
      3. Soma acumulada: quantos pixels têm tom menor ou igual a cada valor.
        4. 
                
      4. Reescala o acumulado para 0–255. O max(..., 1) evita dividir por zero em uma imagem de uma cor só.
        5. 
                
      5. Troca cada pixel pelo valor acumulado do seu tom.
        6. 
              
      
            
      
          
      5. 
          
    5. Escala de 0 a 1. Dividimos tudo por 255 e deixamos a matriz no formato (96, 96, 1): altura,
            largura e 1 canal. Por quê: redes neurais treinam melhor com números pequenos.
            
      
              Ver no código
              
      
              
        
                
      1. As etapas 1 a 4 em sequência: a saída de uma é a entrada da próxima.
        2. 
                
      2. Etapa 5: valores entre 0 e 1.
        3. 
                
      3. Formato (96, 96, 1) em float32, que é o que a CNN espera.
        4. 
                
      4. Se pedido, devolve também as imagens intermediárias (usadas nas figuras e no botão “Ver o que a rede vê”).
        5. 
              
      
            
      
          
      6. 
        
    
      
    

      
      
    
        
    5 Divisão dos dados
    
        
    Separamos as fotos em três grupos: um para a rede aprender, um para acompanhar o treino e um para a
          prova final.
    
        
    
          
    ConjuntoUsoProporção
    
          
            
    Treinoa rede ajusta os pesos olhando essas fotos~70%
    
            
    Validaçãoacompanha o treino e decide quando parar~15%
    
            
    Testeavaliação final, usado uma única vez~15%
    
              
        
    
        
    Cuidado: fotos tiradas em sequência são quase idênticas. Se uma fosse para o
          treino e a vizinha para o teste, a rede “já teria visto” a foto do teste e a nota ficaria falsamente alta.
          Por isso sorteamos blocos de fotos seguidas, e não fotos soltas.
    
        
      
          
    1. Separar por pessoa. A divisão é feita para cada integrante, para que todos apareçam nos três
            conjuntos. Cada pessoa precisa de pelo menos 3 fotos (uma para cada conjunto).
      2. 
          
    2. Agrupar em blocos de fotos seguidas. Os blocos têm até 10 fotos. Se a pessoa tiver poucas fotos,
            os blocos ficam menores (tamanho n // 7), para formar pelo menos ~7 blocos e sobrar algum para o treino.
      3. 
          
    3. Embaralhar os blocos. A ordem dos blocos é sorteada com a semente 42, então a divisão é sempre
            a mesma a cada treino.
      4. 
          
    4. Distribuir. ~15% dos blocos vão para o teste, ~15% para a validação (pelo menos 1 bloco em cada)
            e o resto para o treino.
            
      
              Ver no código
              
      
              
        
                
      1. Sorteador com a semente 42: o sorteio se repete igual a cada execução.
        2. 
                
      2. Passo 1: as fotos desta pessoa, na ordem em que foram tiradas.
        3. 
                
      3. Para o programa com uma mensagem clara se alguém tiver menos de 3 fotos.
        4. 
                
      4. Passo 2: tamanho do bloco: até 10 fotos, menor quando há poucas fotos.
        5. 
                
      5. Passo 2: corta a lista de fotos em blocos seguidos.
        6. 
                
      6. Passo 3: embaralha a ordem dos blocos (as fotos dentro de cada bloco continuam juntas).
        7. 
                
      7. Passo 4: ~15% dos blocos para teste (pelo menos 1).
        8. 
                
      8. Passo 4: os primeiros blocos vão para o teste, os seguintes para a validação e o resto para o treino.
        9. 
                
      9. Devolve as posições das fotos de cada conjunto.
        10. 
              
      
            
      
          
      5. 
        
    
        
    Quantas fotos ficaram em cada conjunto
    
        
    
      
    

      
      
    
        
    6 Aumento de dados
    
        
    Para a rede não decorar as fotos de treino, criamos versões levemente modificadas de cada uma,
          simulando situações reais.
    
        
    Com poucas fotos, a rede tende a decorar as imagens de treino (overfitting) em vez de aprender o
          rosto. Cada foto de treino ganha 3 cópias modificadas, e cada cópia passa por estes passos, com valores sorteados:
    
        
      
          
    1. Espelhar (50% de chance): simula o rosto virado para o outro lado.
      2. 
          
    2. Deslocar até 8 pixels em qualquer direção: simula o rosto fora do centro. A borda que aparece é
            preenchida repetindo os pixels da beirada.
      3. 
          
    3. Mudar contraste e brilho: o contraste é multiplicado por um valor entre 0,8 e 1,2 e o brilho
            muda até ±0,1. Simula iluminações diferentes.
      4. 
          
    4. Somar um ruído pequeno a cada pixel: simula uma câmera de qualidade pior.
      5. 
          
    5. Manter os valores entre 0 e 1.
            
      
              Ver no código
              
      
              
        
                
      1. Passo 1: sorteia um número entre 0 e 1; metade das vezes espelha.
        2. 
                
      2. Espelhar é inverter a ordem das colunas da matriz.
        3. 
                
      3. Passo 2: sorteia o deslocamento vertical e horizontal, de −8 a 8 pixels.
        4. 
                
      4. Aumenta a imagem com 8 pixels de borda repetindo a beirada (mode="edge")...
        5. 
                
      5. ...e recorta 96×96 numa posição deslocada.
        6. 
                
      6. Passo 3: afasta ou aproxima cada pixel do cinza médio (contraste) e soma um valor (brilho).
        7. 
                
      7. Passo 4: ruído com média 0 e desvio 0,02, diferente para cada pixel.
        8. 
                
      8. Passo 5: corta o que passou de 1 ou ficou abaixo de 0.
        9. 
              
      
            
      
          
      6. 
        
    
        
    O aumento é aplicado apenas no treino. Validação e teste usam as fotos reais, porque precisam medir
          o desempenho em situações verdadeiras. No fim, o treino tem 4 vezes mais imagens: as originais e 3 cópias.
    
        
    
          Ver no código
          
    
          
      
            
    1. Começa com as fotos originais de treino.
      2. 
            
    2. Repete 3 vezes: uma cópia modificada de cada foto por vez.
      3. 
            
    3. O rótulo não muda: a foto modificada continua sendo da mesma pessoa.
      4. 
            
    4. Junta tudo em uma única matriz de treino.
      5. 
          
    
        
    
        
      
    

      
      
    
        
    7 Arquitetura da CNN
    
        
    A rede olha a imagem em camadas: as primeiras encontram bordas, as seguintes juntam bordas em partes
          do rosto, e as últimas decidem de quem é o rosto.

    O que acontece com a foto dentro da rede
    
        
      
          
    1. Convolução 3×3 + ReLU. Pequenos filtros de 3×3 deslizam pela imagem e respondem quando
            encontram o padrão que procuram (uma borda, uma curva...). Cada filtro gera um “mapa” de onde encontrou o padrão.
            Os valores dos filtros não são escritos por nós: eles são aprendidos no treino. A ReLU (max(0, x))
            zera os valores negativos, o que permite à rede aprender relações não lineares.
      2. 
          
    2. MaxPooling 2×2. Cada janela 2×2 vira o seu maior valor: a imagem cai pela metade (96 → 48) e a
            rede passa a tolerar pequenos deslocamentos.
      3. 
          
    3. Repetir 4 vezes, com cada vez mais filtros (32, 64, 128, 128). A imagem fica menor (até 6×6) e
            mais “profunda”: as camadas finais combinam os padrões das anteriores em partes do rosto.
      4. 
          
    4. Flatten. Os 128 mapas de 6×6 viram uma única lista de 4608 números.
      5. 
          
    5. Dropout 50%. Durante o treino, metade desses números é desligada ao acaso, para a rede não
            depender de poucos neurônios (combate o overfitting).
      6. 
          
    6. Camada densa (128 neurônios). Combina todas as características encontradas.
      7. 
          
    7. Pontuações e softmax. Uma pontuação por integrante; o softmax transforma as pontuações em
            probabilidades que somam 1 (ex.: ana 92%, bruno 5%, carla 3%).
            
      
              Ver no código
              
      
              
        
                
      1. A entrada: uma imagem 96×96 com 1 canal (cinza).
        2. 
                
      2. Passo 1: 32 filtros 3×3 com ReLU. padding="same" mantém o tamanho 96×96.
        3. 
                
      3. Passo 2: pooling 2×2, de 96 para 48.
        4. 
                
      4. Passo 3: o segundo bloco, com 64 filtros (de 48 para 24 no pooling).
        5. 
                
      5. Passo 3: o quarto bloco; os mapas desta camada são usados no Grad-CAM.
        6. 
                
      6. Passo 4: 6×6×128 vira um vetor de 4608 números.
        7. 
                
      7. Passo 5: desliga 50% dos valores ao acaso (só durante o treino).
        8. 
                
      8. Passo 6: a camada densa com 128 neurônios e ReLU.
        9. 
                
      9. Passo 7: uma pontuação por integrante (sem ativação).
        10. 
                
      10. Passo 7: o softmax transforma as pontuações em probabilidades.
        11. 
                
      11. O otimizador Adam, que ajusta os pesos no treino (seção 8).
        12. 
                
      12. A medida de erro: entropia cruzada, com os rótulos como números 0, 1, 2...
        13. 
              
      
            
      
          
      8.

    8 Treinamento
    
        
    A rede começa com pesos aleatórios e, foto após foto, ajusta esses pesos para errar cada vez menos.
    
        
      
          
    1. Dividir o treino em lotes de 32 fotos. Uma passada completa por todas as fotos de treino é uma
            época.
      2. 
          
    2. Prever. Para cada foto do lote, a rede dá a probabilidade de cada integrante.
      3. 
          
    3. Medir o erro. A entropia cruzada: erro = −log(probabilidade dada à pessoa certa).
            Se a rede deu 0,9 para a pessoa certa, o erro é 0,1; se deu 0,1, o erro é 2,3.
      4. 
          
    4. Ajustar os pesos. O backpropagation calcula quanto cada peso contribuiu para o erro, e
            o otimizador Adam muda cada peso um pouco na direção que diminui o erro.
      5. 
          
    5. Conferir na validação. No fim de cada época, a rede é testada nas fotos de validação (que ela não
            usa para aprender).
      6. 
          
    6. Parar na hora certa. São no máximo 60 épocas. Se o erro na validação não melhorar por 10 épocas
            seguidas, o EarlyStopping para o treino e devolve os pesos da melhor época.
            
      
              Ver no código

        4.

        5.

    12 Perguntas prováveis na apresentação
    
        
    Dados e pré-processamento
    
        
    
          
    Por que recortar em vez de só redimensionar?
    
          
    Redimensionar uma foto retangular para quadrado achataria o rosto.
    
          
    Por que tons de cinza?
    
          
    A identidade está na forma do rosto, não na cor. Com 1 canal a rede fica menor e depende menos da iluminação.
    
          
    Por que a média de blocos antes de reduzir?
    
          
    Pegar só 1 pixel a cada 5 (ou a cada 30, em fotos grandes) gera serrilhado. A média resume todos os pixels do bloco.
    
          
    O que a equalização faz?
    
          
    Usa o histograma acumulado para espalhar os tons de cinza de 0 a 255, deixando fotos claras e escuras parecidas.
    
          
    Por que dividir em blocos de fotos seguidas?
    
          
    Fotos seguidas são quase iguais. Separá-las ao acaso colocaria “gêmeas” no treino e no teste, inflando a nota.
    
          
    Por que aumento de dados só no treino?
    
          
    O teste precisa medir o desempenho em fotos reais.
    
        
    
        
    A rede
    
        
    
          
    Por que CNN e não uma rede comum (densa)?
    
          
    O mesmo filtro percorre a imagem inteira, então a rede precisa de muito menos parâmetros e reconhece o padrão em qualquer posição.
    
          
    Quantos parâmetros tem uma convolução?
    
          
    3 · 3 · canais_de_entrada · filtros + filtros (o último termo é o bias). Por exemplo, conv2 tem 3·3·32·64 + 64 = 18.496. A tabela da seção 7 mostra todas as camadas.
    
          
    O que faz o pooling?
    
          
    Reduz a imagem pela metade (menos contas) e torna a rede tolerante a pequenos deslocamentos.
    
          
    Para que serve o dropout?
    
          
    Desligar neurônios ao acaso obriga a rede a não depender de poucos deles, o que reduz o overfitting.
    
          
    Por que softmax?
    
          
    Ele transforma as pontuações da última camada em probabilidades que somam 1, uma para cada integrante.
    
          
    O que são época e batch?
    
          
    Época é uma passada completa pelo treino. Batch é o grupo de fotos (32) usado em cada ajuste dos pesos.
    
          
    Como a rede aprende?
    
          
    Ela calcula o erro, o backpropagation calcula quanto cada peso contribuiu para ele, e o Adam ajusta os pesos para reduzir o erro.
    
        
    
        
    Métricas
    
        
    
          
    Precisão × recall?
    
          
    A precisão olha a coluna da matriz: das vezes que a rede disse X, quantas eram X. O recall olha a linha: das fotos de X, quantas a rede acertou.
    
          
    Por que não só a acurácia?
    
          
    Se uma pessoa tiver muito mais fotos, a acurácia pode ser alta mesmo errando as outras.
    
        
    
        
    O site e o reconhecimento ao vivo
    
        
    
          
    Como reconhece várias pessoas ao vivo?
    
          
    Sem detector de rosto, a rede não sabe onde estão os rostos. Por isso a tela é dividida em caixas fixas e cada pessoa se posiciona em uma. Achar rostos em qualquer lugar exigiria um detector (como os do OpenCV), que o trabalho não permite.
    
          
    Quais são as limitações?
    
          
    O rosto precisa estar dentro da caixa (no centro, com 1 pessoa). Além disso, o softmax sempre escolhe alguém; por isso usamos o limiar de 60% para “desconhecido”.
    
          
    Por que a rede roda no servidor e não no navegador?
    
          
    Para usar exatamente o mesmo código Python do treino (preprocessar e o modelo salvo). Assim, não existe uma segunda versão do pré-processamento que poderia ficar diferente.
    
          
    Por que um servidor Node e um processo Python?
    
          
    Cada um faz o que faz melhor: o Node cuida do HTTP (site, rotas, gravação das fotos) e o Python cuida só da rede neural. Eles conversam pelo stdin/stdout, uma linha de JSON por pedido; o Python fica aberto o tempo todo, então o modelo é carregado uma vez só.
    
          
    Como o site mostra o progresso do treino?
    
          
    O servidor Node roda python -m src.treinar e guarda o que ele imprime. A página pergunta a cada segundo como está o treino e lê as linhas “Etapa N/8” e “Epoch N/60” para desenhar a barra.
    
          
    Por que a média de 5 quadros?
    
          
    Para o nome não “piscar” quando um quadro isolado sai diferente. Com ~4 quadros por segundo, a média cobre pouco mais de 1 segundo.
    
          
    O vídeo espelhado não atrapalha a rede?
    
          
    Não: o espelhamento é só visual (CSS). O quadro enviado ao servidor é o original, como as fotos de treino; apenas a posição das caixas é espelhada no desenho.
    
          
    O código desta página pode estar desatualizado?
    
          
    Não: os blocos de código são lidos do próprio arquivo Python pela rota /api/codigo (o servidor recorta a função direto do arquivo .py ou .js), e as métricas vêm do resultados.json gerado no último treino.
